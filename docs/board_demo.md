# RAAS Board Demo Workflow

## Goal

The finished demo runs on Ultra96v2:

1. Zynq PS holds PicoRV32 in reset.
2. PS copies the PicoRV32 firmware binary to the 64 KB boot BRAM at PS address `0xA0000000`.
3. PS preloads DDR with one deterministic MNIST image, packed biases, and packed weights.
4. PS releases PicoRV32 through SW reset at `0xA0030000`.
5. PicoRV32 configures `accelerator_1_0` and AXI DMA, streams the three MLP layers, writes a DDR mailbox at `0x10101000`, and stops.
6. PS polls the mailbox and prints `RAAS PASS` or `RAAS FAIL`.

## Canonical RTL

Use `hw/accelerator_1_0/src` as the only accelerator RTL source for new simulation and packaging work. The older `hw/accelerator_1_0/hdl` copies are stale and should not be used for the board-demo flow.

## Memory Map

| Region | Address | Owner/Use |
|--------|---------|-----------|
| Accelerator AXI-Lite | `0x40000000` | PicoRV32 configures inference registers |
| AXI DMA | `0x40010000` | PicoRV32 schedules MM2S/S2MM transfers |
| Pico boot BRAM, Pico view | `0x00000000` | Pico reset vector and firmware |
| Pico boot BRAM, PS view | `0xA0000000` | PS firmware loader |
| SW reset | `0xA0030000` | PS writes `0` hold reset, `1` release reset |
| Image input | `0x10000000` | Two Q1.4.11 pixels per 32-bit word |
| Biases | `0x10001000` | One `[neuronB\|neuronA]` word per neuron pair |
| Weights | `0x10002000` | `[neuronB_i\|neuronA_i]` for each input `i` |
| Hidden 1 output | `0x10100000` | Accelerator layer output |
| Hidden 2 output | `0x10100100` | Accelerator layer output |
| Final output | `0x10100200` | Five packed score words |
| Mailbox | `0x10101000` | Pico writes status/result, PS reads |

Accelerator registers remain:

| Offset | Value |
|--------|-------|
| `slv_reg0` at `0x00` | `784` |
| `slv_reg1` at `0x04` | `0x00100010` |
| `slv_reg2` at `0x08` | `10` |
| `slv_reg3` at `0x0C` | bit 0 `NN_EN`, bit 1 `DATA_RDY` |
| `slv_reg4` at `0x10` | bit 0 `BSY` |

## Build And Test

From the repository root:

```sh
python3 tools/export_raas_demo_data.py
make -C sw/picorv32
/home/tam/Documents/app/2025.2.1/Vivado/bin/vivado -mode batch -source sim/run_xsim.tcl
```

Then build `sw/vitis/RAS_app` in Vitis against `RAS_wrapper.xsa`, program the bitstream, and run the PS app. The PS console should report mailbox `DONE`, predicted digit equal to the expected label, exact packed score-word match against the generated golden output, and finally `RAAS PASS`.

## Generated Artifacts

- `sw/common/raas_demo_data.h`: C arrays consumed by the PS loader.
- `sim/raas_demo_vectors.svh` and `sim/raas_demo_*.mem`: metadata plus `$readmemh` payloads consumed by the XSIM smoke test.
- `sw/vitis/RAS_app/src/pico_firmware_image.h`: generated by `make -C sw/picorv32` and embedded in the PS loader.
